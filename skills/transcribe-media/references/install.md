# Инструкция ассистенту: установка из локального чата

Инструкция подходит для двух случаев:

1. **Пакет.** Пользователь распаковал ZIP или скачал репозиторий с GitHub; скилл ещё не зарегистрирован. Прочитай инструкцию **до регистрации скилла**. Папка скилла — `<корень-пакета>/skills/transcribe-media`. На шаге выбора спроси клиент и область — мастер скопирует скилл.
2. **Скилл уже на месте.** Его поставили из GitHub командой `/plugin install` (Claude Code) или `npx skills add` (Codex и другие), и ты читаешь этот файл из установленной папки. Папка скилла — каталог с `SKILL.md`, на уровень выше этого файла. На шаге выбора вызови `select --in-place`: мастер поставит программы и настройки, а скилл не копирует.

Ниже `<папка-скилла>` — абсолютный путь к папке скилла. Сначала проверь, что можешь запускать локальные команды. Если нет, попроси открыть папку как локальный проект или рабочую папку. Не утверждай, что можешь установить пакет из обычного браузерного чата без доступа к компьютеру.

## Первый запуск и Node.js

Первый bootstrap выполняют `scripts/start.ps1` на Windows и `scripts/start.sh` на macOS/Linux в папке скилла. В режиме `--chat` они не задают вопросы через терминальный ввод. Веди согласование в чате и запускай команды сам, только после нужного согласия пользователя.

1. Покажи, что будет проверяться, и запусти безопасный план. На Windows:

   ```text
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<папка-скилла>\scripts\start.ps1" --chat --plan
   ```

   На macOS/Linux:

   ```text
   sh "<папка-скилла>/scripts/start.sh" --chat --plan
   ```

   `--plan` не проверяет версии программ, не скачивает и не устанавливает файлы.

2. Объясни, что проверка кандидата Node запускает локальный исполняемый файл. После отдельного согласия пользователя повтори команду с `--chat --allow-check` вместо `--chat --plan`.

3. Запускатель ищет Node.js 22+ не только в PATH, но и в стандартных местах (`Program Files\nodejs`, папка программ winget, путь от прежних версий мастера). Если Node.js найден, запускатель стартует мастер **в фоне** (`serve --detach --open`), сразу печатает JSON сессии и завершается; панель установки сама открывается в браузере. Команда возвращается за несколько секунд — её не нужно запускать в фоновом режиме клиента. Если Node.js нет, запускатель показывает план установки через winget и завершается с кодом 2 и словом `node-required`. Не пытайся запускать `serve` без подходящего Node и не проси пользователя вводить команды, если локальный исполнитель доступен.

4. На Windows Node.js ставится способом его разработчиков: `winget install --id OpenJS.NodeJS.LTS` — официальный установщик Node.js LTS с nodejs.org. Предупреди, что Windows может показать окно «Разрешить изменения?» и в нём нужно нажать «Да». После отдельного согласия на этот план запусти:

   ```text
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<папка-скилла>\scripts\start.ps1" --chat --allow-check --allow-node-install
   ```

   На macOS/Linux используй `sh "<папка-скилла>/scripts/start.sh" --chat --allow-check --allow-node-install`. На macOS Node.js ставится через Homebrew (`brew install node`); если Homebrew нет, запускатель предложит установить его с <https://brew.sh> (нужен пароль администратора — это делает сам пользователь в Терминале) или Node.js LTS с <https://nodejs.org/>. На Linux пока используется прежняя загрузка архива Node.js.

   Флаг разрешает только установку Node.js. Он не разрешает установку FFmpeg, yt-dlp или самого скилла. Если на Windows нет winget, запускатель предложит установить «Установщик приложений» из Microsoft Store (<https://apps.microsoft.com/detail/9NBLGGH4NNS1>) или Node.js LTS с <https://nodejs.org/> — передай это пользователю и повтори запуск после установки.

При успехе запускатель печатает JSON: `url` панели, `sessionPath`, `id`, `nodePath`, `pid` фонового мастера и `log` — путь к журналу фонового мастера (смотри его, если мастер не отвечает). Сразу дай пользователю ссылку `url`: панель показывает ход установки. Для следующих команд используй выданный `nodePath` и путь `<папка-скилла>/scripts/installer.mjs`. `sessionPath` передавай как `--session`; не читай и не выводи содержимое файла сессии, в нём есть capability для локального управления.

Если чатовый native bootstrap недоступен или клиент не может запускать локальные команды, честно скажи, что первый запуск нужно выполнить через терминал. На Windows пользователь может дважды щёлкнуть `Установить.cmd` в корне пакета или запустить `<папка-скилла>\scripts\start.ps1` в PowerShell; на macOS/Linux — запустить `sh <папка-скилла>/scripts/start.sh`. После установки Node снова откройте папку в локальном чате и продолжите установку там. Не обещай, что браузерный чат без доступа к локальному компьютеру выполнит установку без команд пользователя.

## Установка скилла и настройка

Дальше команды — клиенты уже запущенного `serve`. Для PowerShell используй оператор вызова `&`; в POSIX shell заключай пути в кавычки. В каждом вызове передавай клиентские аргументы как массив, а `--session` добавляй через обёртку.

PowerShell:

```powershell
$nodePath = '<nodePath>'
$installerPath = '<папка-скилла>\scripts\installer.mjs'
$sessionPath = '<sessionPath>'
function Invoke-InstallerClient {
  param([string[]]$ClientArgs)
  & $nodePath $installerPath @ClientArgs --session $sessionPath
}
Invoke-InstallerClient -ClientArgs @('status')
Invoke-InstallerClient -ClientArgs @('select', '--agent', 'codex', '--scope', 'user')
```

macOS/Linux:

```sh
node_path='<nodePath>'
installer_path='<папка-скилла>/scripts/installer.mjs'
session_path='<sessionPath>'
installer_client() {
  "$node_path" "$installer_path" "$@" --session "$session_path"
}
installer_client status
installer_client select --agent codex --scope user
```

Примеры показывают аргументы для `status` и `select`; остальные команды ниже — также аргументы этой обёртки. Не передавай ключи в argv. Не начинай интерактивный терминальный `start`, пока управляемый чатовый процесс активен.

1. Спроси, где использовать скилл: Codex, Claude Code или оба; во всех проектах или в одном проекте. Затем передай выбор:

   ```text
   select --agent codex|claude|both --scope user|project [--project PATH]
   ```

   Путь проекта передавай только для области `project`.

   Если скилл уже на месте (случай 2 в начале), клиент и область не спрашивай — вызови `select --in-place`. В плане установки тогда нет копирования скилла, только недостающие программы.

2. Перед проверкой программ объясни, что именно будет запущено, и получи согласие. Затем выполни `inspect --allow-check`. В этой команде проверяются Node.js, FFmpeg, ffprobe, yt-dlp и компонент EJS; программы ищутся и вне PATH (winget, Program Files, Chocolatey, Scoop). Команда ничего не устанавливает.

3. Выполни `plan` и покажи пользователю список `result.planSteps` — это план человеческими словами — и предупреждения `result.planWarnings`. На Windows недостающее ставится через winget пакетами разработчиков (`OpenJS.NodeJS.LTS`, `Gyan.FFmpeg.Essentials`, `yt-dlp.yt-dlp`; вместе с yt-dlp winget ставит Deno и FFmpeg), а yt-dlp, установленный через pip, обновляется командой `pip install -U "yt-dlp[default]"`. На macOS программы ищутся также в папках Homebrew, MacPorts и pip, а недостающее ставится через Homebrew (`brew install node ffmpeg yt-dlp`; yt-dlp из Homebrew уже содержит EJS и Deno); если Homebrew нет, мастер остановится на шаге «установите Homebrew с brew.sh». В личную папку на Windows и macOS ничего не скачивается. Установка требует отдельного согласия на текущий план. Только после него используй полученный `planId`:

   ```text
   install --allow-install --plan-id <planId>
   ```

   Установка через winget может идти несколько минут: запускай команду с тайм-аутом не меньше 10 минут или в фоне. Пока она идёт, ход установки печатается в stderr понятными строками («FFmpeg: установка через winget идёт 45 с») — пересказывай его пользователю; итоговый JSON приходит в stdout. Для согласованного обновления существующей установки добавь `--update`. Если план изменился или команда отклонила устаревший `planId`, покажи новый план и запроси согласие снова. Если `result.error` или текст ошибки называют программу и причину — передай их пользователю дословно.

   EJS — компонент yt-dlp, который проходит проверку YouTube на JavaScript. Без него YouTube-ссылки не работают, а локальные файлы, TikTok и Instagram работают; установка скилла при этом не останавливается, мастер показывает предупреждение. Если состояние `manual` — на компьютере не хватает winget: передай пользователю шаг из `planSteps` и после его выполнения повтори `inspect` и `plan`.

4. Предложи подключить Deepgram или AssemblyAI сейчас либо позже. После установки мастер сам открывает в браузере страницу настроек — адрес панели `url` с `/setup` на конце; в панели есть и кнопка «Настройки». Дай пользователю эту ссылку и объясни: на странице есть ссылки на регистрацию и создание ключа; ключ вставляется в поле карточки сервиса, кнопка «Сохранить и проверить» отправляет один бесплатный запрос без аудио, отклонённый ключ не сохраняется. Дождись статуса: через `status` смотри `connection.ready` (`true` — у основного сервиса проверенный ключ) и `connection.providers.*.verification.status`. Не проси ключ в чате, не читай его из файла, панели, окружения или вывода; если пользователь вставил ключ в чат, не используй его и попроси ввести на странице. Если сервис пока не нужен, вызови `skip-provider`.

5. Предложи проверить настройки расшифровки. По умолчанию язык определяется автоматически (`auto`, у AssemblyAI запасной — русский), длина одной строки субтитров — 30 секунд, форматы `txt,srt,vtt`, разделение участников выключено. Пользователь может поменять их на странице настроек или ответить в чате; тогда передай выбранное через `configure` с нужными `--language`, `--interval`, `--formats`, `--diarize` или `--no-diarize`, `--speakers auto|N` и `--output PATH`. Если пользователь согласен со значениями по умолчанию, вызови `configure` без параметров.

6. Покажи итоговую сводку и вызови `finish` после подтверждения сохранённых параметров. Отложенный ключ не препятствует завершению установки. Установка скилла сама по себе не отправляет медиа в API.

## Состояние, остановка и продолжение

- Переданный через обёртку `status` возвращает безопасный снимок состояния. Она добавляет `--session` автоматически. Панель — локальная и доступна по URL из результата запуска; закрытие вкладки не закрывает мастер. Показывай только измеренный процент, когда есть фактические `loaded` и `total`.
- Долгая команда клиента ждёт завершения операции и опрашивает её результат. При необходимости запроси `status`; не запускай вторую установку параллельно.
- Для отмены используй `cancel`. Во время низкоуровневой установки состояние может стать `cancel-pending`: дождись безопасного завершения текущей операции. Установленные файлы не удаляются.
- Для штатного закрытия вызови `stop`. Он дожидается безопасного завершения и закрывает процесс. Панель сама по себе процесс не останавливает; без управляющих запросов процесс завершается по idle timeout 30 минут, активную операцию timeout не обрывает.
- Если процесс завершился аварийно, сначала проверь `status`. При недоступной сессии предложи продолжить только через основной CLI с аргументами `serve --recover --state PATH --node PATH`; используй тот же `--state` и выданный `nodePath`. Для этого запуска применяй показанную выше форму вызова своей ОС, но не client-обёртку и не `--session`. Восстанавливай лишь собственную сессию с подтверждённым завершившимся PID; не удаляй lock или session вручную. Если процесс ещё жив или его статус неизвестен, не запускай второй мастер.
- После завершения попроси открыть новый чат в выбранном клиенте (если скилл уже был на месте, можно продолжать в этом чате). Открыть нужно локальную папку или проект; наличие отдельной кнопки клиента с конкретным названием не обещай. Реальное обнаружение скилла целевыми установками пока не проверено. Если скилл не появился, предложи перезапустить клиент и только затем отдельно диагностировать.

## Ручной CLI

Полная справка основного CLI транскрибации: `node <папка-скилла>/scripts/cli.mjs help`. Ручной сценарий приведён в [usage.md](usage.md). Сверяй команды с актуальной справкой и не выдумывай флаги.

## Страница настроек после установки

Если пользователь просит показать настройки, поменять или добавить ключ, подключить сервис («Помоги подключить сервис распознавания»), работай в локальном проекте с доступом к командам. Если это обычный браузерный чат без локального исполнителя, попроси открыть папку в Codex или Claude Code либо предложи запустить подключение в терминале.

Открой страницу настроек фактическим путём к Node.js и пакету:

```text
node "<папка-скилла>/scripts/installer.mjs" settings
```

Команда запускает локальный сервер в фоне, открывает страницу в браузере и сразу печатает JSON: `url` страницы, `panelUrl`, `sessionPath`, `reused`. Если сервер уже работает, она открывает ту же страницу и второй сервер не запускает. Дай пользователю ссылку `url`. Пользователь может открыть страницу и сам — командой `/transcribe-settings` в Claude Code (если скилл поставлен плагином — `/transcribe-media:transcribe-settings`) или `$transcribe-settings` в Codex.

Не заканчивай сопровождение фразой «введите ключ сами». Объясни, где на странице регистрация, создание ключа и поле ключа, и дождись результата проверки. Пароль, почту, CAPTCHA и оплату пользователь вводит только на сайте сервиса. Значение API-ключа никогда не проси в чате и не передавай в аргументах команд.

Ключ сохраняется в общем хранилище пользователя ОС. Установка в области `project` и передача `--config` не создают изоляцию ключа для проекта. Новый ключ заменяет старый только после успешной проверки или если сервис недоступен; отклонённый ключ (401/403) не записывается. Ключ из переменной окружения важнее сохранённого, страница его не удаляет.

Язык, длину субтитра, форматы, разделение участников и папку результата можно менять из чата без страницы: `cli.mjs setup --language … --interval …` и т. п. Выполни команду и одной строкой сообщи, что изменилось.

В терминале без браузера ключ вводится скрыто с той же проверкой:

```text
node "<папка-скилла>/scripts/installer.mjs" connect
```
