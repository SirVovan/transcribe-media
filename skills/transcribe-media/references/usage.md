# Использование

Все команды запускай через абсолютный путь к `skills/transcribe-media/scripts/cli.mjs`, вычисленный от установленной папки скилла. Полный список команд и флагов показывает команда `help`.

## Мастер установки и настройки

Для первого запуска из чата читай [install.md](install.md) до регистрации скилла. Native bootstrap сначала показывает безопасный план (`--chat --plan`), затем после согласий проверяет Node (`--chat --allow-check`) и при необходимости устанавливает приватную копию Node (`--chat --allow-check --allow-node-install`). Этот bootstrap не устанавливает остальные зависимости и не заменяет согласие на план мастера.

Из терминала мастер запускается двойным щелчком `Установить.cmd` на Windows или через `scripts/start.ps1` / `scripts/start.sh` папки скилла. Если Node уже доступен, его можно запустить напрямую:

```text
node "<абсолютный-путь-к-пакету>/skills/transcribe-media/scripts/installer.mjs" start
node "<абсолютный-путь-к-пакету>/skills/transcribe-media/scripts/installer.mjs" serve
```

`start` задаёт вопросы в терминале; `serve` запускает процесс с локальной панелью для команд из чата и создаёт приватный session descriptor. Синтаксис чата и последовательность согласий смотри в `УСТАНОВИТЬ-ИЗ-ЧАТА.md`. Закрытие вкладки не закрывает `serve`; для штатной остановки используй `stop` с тем же `--session`.

После завершения мастера открой новый чат в выбранном клиенте. Язык по умолчанию — «определять автоматически» (`auto`), длина одной строки субтитров — 30 секунд. Ключ можно добавить позже; не отправляй его в чат.

### Страница настроек

Ключи сервисов, основной сервис и настройки расшифровки собраны на одной локальной странице `/setup`. Она открывается:

- по прямой просьбе в чате показать настройки, поменять или добавить ключ, подключить сервис — ассистент запускает команду ниже и даёт ссылку;
- слэш-командой `/transcribe-settings` в Claude Code или `$transcribe-settings` в Codex (отдельный скилл, вызывается только явно);
- кнопкой «Настройки» в панели установки.

```text
node "<путь-к-пакету>/skills/transcribe-media/scripts/installer.mjs" settings
```

Команда запускает локальный сервер в фоне, открывает страницу в браузере и сразу печатает JSON с `url`. Если сервер уже работает, она открывает ту же страницу и второй сервер не запускает. Сервер сам выключается через 30 минут без действий. `--config` задаёт конфигурацию, но не изолирует ключ: ключ хранится для пользователя ОС даже при установке с областью `project`.

На странице пользователь регистрируется и создаёт ключ по ссылкам, вставляет ключ и нажимает «Сохранить и проверить». Это согласие на один бесплатный запрос без аудио; ключ, который сервис отклонил (401/403), не сохраняется. Если пользователь вставил ключ в чат, не используй его: открой страницу и попроси ввести там.

В терминале ключ вводится скрыто: `installer.mjs connect` (с той же проверкой, что на странице) или `cli.mjs provider add NAME` (без проверки).

### Настройки из чата без страницы

Язык, длину субтитра, форматы, разделение участников по умолчанию и папку результата ассистент меняет сам командой `setup` и одной строкой сообщает, что изменилось:

```text
node "<абсолютный-путь-к-скиллу>/scripts/cli.mjs" setup --language auto --interval 30
node "<абсолютный-путь-к-скиллу>/scripts/cli.mjs" setup --formats txt,srt --diarize --output "АБСОЛЮТНЫЙ_ПУТЬ"
```

Длина субтитра (`--interval`, по умолчанию 30 с) — максимальная длина одной реплики SRT/VTT в секундах. Реплика кончается раньше на конце предложения, на паузе дольше 0,5 с или при смене спикера. Действует, только когда сервис вернул тайминги слов; у субтитров источника (YouTube) границы фраз сохраняются. `transcript.txt` делится на абзацы: после конца предложения и паузы от 2 с или когда абзац набрал около 600 знаков.

`setup` проверяет язык для основного сервиса. Разовые параметры одной расшифровки («на английском», «с разделением по спикерам») передаются флагами `transcribe` и настройки не меняют. Основной провайдер пакета — Deepgram; пользователь может выбрать AssemblyAI.

## Установка

Ручная установка через основной CLI сохраняется. Пакет копируется целиком в область выбранного агента. Укажи агента (`codex`, `claude`, `both`) и область (`user`, `project`); для `project` передай абсолютный путь проекта через `--project-root`. Сначала вызови `install` без разрешения на загрузки, чтобы показать план. `--allow-install` добавляй только после явного согласия пользователя на действия из плана. Обновление требует отдельного `--update`.

```text
node "<абсолютный-путь-к-скиллу>/scripts/cli.mjs" install --agent codex --scope user
node "<абсолютный-путь-к-скиллу>/scripts/cli.mjs" install --agent both --scope project --project-root "АБСОЛЮТНЫЙ_ПУТЬ" --allow-install
```

Первый пример только показывает план. Второй пример выполняет установку, поэтому запускай его только после явного согласия. У `doctor` доступны режимы `doctor` и `doctor --repair`; скачивание/установка при исправлении требует `--allow-install`.

## Ключи провайдеров

Добавление ключа — отдельное действие с отдельным согласием. Основной путь — страница настроек; в терминале — `provider add deepgram` или `provider add assemblyai` со скрытым вводом. Не передавай значение ключа аргументом и не проси его в сообщении. Переменные окружения `DEEPGRAM_API_KEY` и `ASSEMBLYAI_API_KEY` поддерживаются, но агент не должен устанавливать их автоматически.

`provider status` показывает наличие и статус без проверки API. `saved` означает «сохранён, не проверен»; проверку показывает страница настроек. Добавление/удаление ключа не включает согласие на распознавание в облаке.

## Транскрибация

До выполнения покажи источник и согласованные настройки: language, interval, formats, provider, model, diarize, speakers, cookies и режим обработки. Для локального файла также сообщи, что перед платным запросом будет проверена неизменность источника. URL платформы обрабатывается через yt-dlp. Для прямого HTTP(S)-URL CLI сначала скачивает свежую копию в папку задания, вычисляет SHA-256 этих байтов, затем строит cache key и проверяет кэш. Такая загрузка нужна для идентификации содержимого и сама по себе не означает отправку в облако; платная отправка возможна только позже, если не найден подходящий кэш или субтитры и пользователь разрешил `--allow-cloud`.

```text
node "<абсолютный-путь-к-скиллу>/scripts/cli.mjs" transcribe "ПУТЬ_К_ФАЙЛУ_ИЛИ_URL" --formats txt,srt,vtt
```

Обычная транскрибация использует подходящий кэш или субтитры; облако требует явного `--allow-cloud`. Получи согласие на возможный платный запрос перед вызовом и включи флаг только после согласия. `transcribe INPUT --plan` показывает параметры и завершается до инспекции источника, загрузки медиа и обращения к cookies; в ответе есть `formTitle` и `formPreview` (вопрос и выровненный блок параметров для формы подтверждения, см. SKILL.md), `summary` (те же параметры строками) и `settingsCommand`. Для доступа через cookies отдельно получи согласие и используй `--allow-cookies` вместе с `--cookies PATH` или `--cookies-browser BROWSER`. Никогда не приравнивай наличие API-ключа к согласию. `--source-proxy direct` заставляет yt-dlp читать ссылку напрямую, мимо прокси из переменных окружения и системных настроек; `setup --source-proxy direct` сохраняет это, `system` возвращает прежнее поведение. Это ответ на код `SOURCE_BOT_CHECK` («источник принял запрос за автоматический»).

После запуска сообщи абсолютный путь результата и фактический источник транскрипта: cache, subtitles или API. При языке `auto` ответ содержит `languageNote` — передай строку «Определён язык: …». Тайминги могут быть пословными, фразовыми либо отсутствовать. При diarize результат использует метки «Спикер N»; это не идентификация людей. Число спикеров — подсказка API, когда она поддерживается.

## Resume, reformat и cleanup

Повтор того же файла с теми же параметрами (запрос, длина субтитра, форматы) новую папку не создаёт: CLI находит готовую папку результата, в которой все файлы на месте, и отвечает `reused: true` с её путём `outputDir`. Другая длина субтитра или другие форматы дают новую папку из кэша без оплаты.

`list` показывает последние запуски (до 20, новые первыми): `runId`, название, статус, время изменения, папку результата у завершённых и `action` — `resume` (есть задание AssemblyAI) или `unlock` (исход отправки неизвестен). Команда ничего не меняет; ею ассистент находит run ID в новом чате.

`resume RUN_ID --allow-cloud` предназначен для ранее сохранённой задачи. Он показывает параметры; при наличии сохранённого результата восстанавливает его локально, иначе для AssemblyAI читает сохранённый ID через GET. Новая загрузка и POST не выполняются. `--allow-cloud` требуется для чтения облачного задания. Если после отправки произошёл timeout или отмена без ID, не запускай запрос повторно.

`unlock RUN_ID` показывает, заблокирована ли повторная отправка файла этой задачи: `not-blocked` — блокировки нет, `confirmation-required` (код выхода 2) — исход прежней отправки неизвестен. `unlock RUN_ID --confirm-uncertain` снимает такую блокировку; запускай его только после явного согласия пользователя на риск двойной оплаты, лучше после проверки истории запросов в кабинете сервиса. Для задания AssemblyAI с сохранённым ID команда отвечает `REQUEST_RESUME` — используй `resume`. Блокировку от принудительно завершённого процесса (`.lock` в `work/requests`) следующий запуск на этом же компьютере снимает сам.

Длинные записи запускай в фоне или с максимальным тайм-аутом команды и не прерывай процесс.

`reformat PATH` локально создаёт новое представление транскрипта в отдельной папке. API не вызывается.

Перед уборкой конкретной задачи покажи список кандидатов:

```text
node "<абсолютный-путь-к-скиллу>/scripts/cli.mjs" cleanup "RUN_ID" --dry-run
```

Само удаление выполняй только после отдельного согласия, повторив команду без `--dry-run`. Удаляются лишь созданные временные файлы данной задачи. Исходник, результат, cache, запись о платном запросе и ключи не являются целями уборки.

Общая уборка прошлых запусков — та же команда без RUN_ID:

```text
node "<абсолютный-путь-к-скиллу>/scripts/cli.mjs" cleanup --dry-run
```

Ответ содержит `items` (вид и путь каждого кандидата, размер), `summary` (строки по видам) и `total`. Без `--dry-run` удаляется:

- временные файлы (`temp`) всех прошлых запусков;
- служебные папки запусков в `work/jobs`, которые больше не нужны: завершённых и отклонённых;
- кэш старше 14 дней вместе с записью «оплачено и завершено» в журнале — иначе повтор файла упрётся в `REQUEST_COMPLETE`; повтор после этого снова платный;
- пустые папки результатов вида `<название>-<RUN_ID>` в папке результатов.

Не трогаются: запуски, изменённые меньше часа назад или с живой блокировкой; папки и записи запусков с неизвестным исходом и заданий AssemblyAI (нужны `unlock` и `resume`); несохранённый ответ сервиса; готовые результаты, исходники, ключи и настройки.

## Типовые ограничения

- Отсутствие авторских субтитров не подтверждается ошибкой доступа: покажи классифицированную ошибку источника.
- Субтитры с фразовыми таймингами не подходят для запроса точных word timestamps.
- Deepgram не получает обещание конкретного числа спикеров; AssemblyAI получает число только как подсказку при включённой диаризации.
- При `uncertain` не повторяй платный POST и не меняй провайдера автоматически; снятие блокировки — только `unlock RUN_ID --confirm-uncertain` с согласия пользователя.
- Отказ сервиса 4xx (неверный ключ, нет средств, нет прав, лимит) не блокирует файл: после исправления причины расшифровку можно запустить снова. При отклонённом ключе ответ содержит `settingsCommand` — открой страницу настроек.
- Сохраняй временные файлы только по явному запросу пользователя через поддерживаемый `--keep-temp`.
