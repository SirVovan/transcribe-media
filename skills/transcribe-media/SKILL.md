# transcribe-media

Используй скилл, когда пользователь просит получить или преобразовать транскрипт, настроить провайдера, проверить зависимости, возобновить существующий запуск или убрать его временные файлы. Поддерживаемые источники: локальный файл, YouTube, TikTok, Instagram Reels, прямой URL медиа и другие сайты, которые читает yt-dlp (Rutube, VK, Дзен, X и т. п.; Threads не читает).

CLI находится в `scripts/cli.mjs` рядом с этим файлом. Вычисли абсолютный путь к каталогу скилла из текущего файла и вызывай CLI через абсолютный путь в кавычках, например `node "/абсолютный/путь/skills/transcribe-media/scripts/cli.mjs" help`. Не меняй cwd вызывающего процесса. Сверяй синтаксис с `help`; не придумывай команду исправления или флаг. Не запускай диагностику без просьбы пользователя. Команды из полей ответа `settingsCommand` и `updateCommand` начинаются с пути к node в кавычках: в Bash, zsh и cmd выполняй их как есть, в PowerShell — с `& ` в начале (без него PowerShell отвечает «Unexpected token»).

В Codex запускай `cli.mjs` и `installer.mjs` сразу с запросом на выполнение вне песочницы: команды читают файлы из домашней папки пользователя, пишут в `%LOCALAPPDATA%\transcribe-media` и папку результата, ходят в сеть, запускают локальный сервер и открывают браузер. Ошибки `EPERM`, `EACCES` или сети, полученные в песочнице, не означают поломку установки: повтори ту же команду вне песочницы, переустановку не предлагай.

Форма выбора (вопрос с вариантами ответа) сама не ставит переносы строк: текст одним абзацем сливается в нечитаемую строку. В любой форме этого скилла пиши вопрос строками: первая строка — коротко, о чём решение; шаги плана, параметры, программы и пути — каждое с новой строки, нумерованно или через «- », смысловые части разделяй пустой строкой; сам вопрос («Запускать?») — отдельной последней строкой. Описание варианта — одна короткая фраза; длинное содержимое — в окно предпросмотра (в Claude Code — поле `preview`) или обычным сообщением перед формой.

## Настройка и установка

Для первой установки и настройки используй мастер. Порядок и согласования описаны в [references/install.md](references/install.md): native bootstrap `scripts/start.ps1` (Windows) или `scripts/start.sh` (macOS/Linux) с `--chat --plan`, затем после отдельных согласий `--chat --allow-check` и, если нужен Node, `--chat --allow-check --allow-node-install`. Для терминала — те же запускатели без `--chat` или `Установить.cmd` в корне пакета. Не обещай режим без участия пользователя, если у клиента нет доступа к локальной папке и командам.

Если скилл поставлен из GitHub (`/plugin install` в Claude Code, `npx skills add`, встроенный установщик скиллов Codex), мастер ещё не запускался. Признак первого запуска — нет файла настроек: Windows `%LOCALAPPDATA%\transcribe-media\config.json`, macOS `~/Library/Application Support/transcribe-media/config.json`, Linux `${XDG_CONFIG_HOME:-~/.config}/transcribe-media/config.json` (проверь только наличие файла; файл ключей не открывай), — или команда `node` не найдена. Тогда до транскрибации скажи, что нужна первая настройка, и с согласия пользователя пройди [references/install.md](references/install.md) в режиме «Скилл уже на месте» (`select --in-place`). В плагине Claude Code команда страницы настроек называется `/transcribe-media:transcribe-settings`.

Мастер управляет выбором клиента и области, проверкой и установкой по показанному плану и настройками; после установки он открывает страницу настроек. Подключение сервиса необязательно. Не запускай проверки, установку или изменение настроек без просьбы пользователя и требуемого согласия. Для существующего установленного пакета предпочитай мастер `scripts/installer.mjs`; синтаксис ручного `setup` и команд установки смотри в `help`.

Если пользователь просит обновить скилл, ставь новую версию пакета по разделу «Для ИИ-ассистента: обновление» в README репозитория https://github.com/SirVovan/transcribe-media: свежий архив, мастер в режиме «Пакет» с тем же клиентом и областью, `install --update`. Не правь файлы установленного скилла вручную и не переписывай этот SKILL.md по README — программа скилла от этого не обновится.

Для явной диагностики по просьбе пользователя используй `doctor`. Он сверяет версии yt-dlp, Node.js и FFmpeg с последними выпусками; статус `update-available` — программы работают, но есть обновления (`inspection.updates`). Исправление и обновление зависимостей выполняется через `doctor --repair`; действия, способные скачать или установить компоненты, требуют отдельного согласия и `--allow-install`.

## Страница настроек и ключи

Ключи Deepgram и AssemblyAI, основной сервис, язык, длина субтитра, форматы, разделение участников и папка результата собраны на локальной странице настроек. Открывай её **только по прямой просьбе** пользователя показать настройки, поменять или добавить ключ, подключить сервис, а также когда CLI вернул `settingsCommand` и пользователь согласен открыть страницу. Выполни `node "<абсолютный-путь-к-скиллу>/scripts/installer.mjs" settings` (через абсолютный путь в кавычках): команда запускает локальный сервер в фоне, открывает страницу в браузере, сразу печатает JSON и не запускает второй сервер, если он уже работает. Дай пользователю ссылку из поля `url` одной строкой. Пользователь сам может открыть страницу командой `/transcribe-settings`.

Никогда не проси ключ в чате, не помещай его в argv, документы, логи или проектный конфиг и не читай файл ключей. Если пользователь вставил ключ в чат, не используй и не повторяй его: открой страницу и попроси ввести ключ там. На странице кнопка «Сохранить и проверить» — согласие пользователя на один бесплатный запрос к сервису без аудио; ключ, который сервис отклонил, не сохраняется. Проверка подтверждает только авторизацию, не баланс. В терминале ключ вводится скрыто: `installer.mjs connect` или `provider add NAME`. `provider status` показывает только наличие ключа. Само наличие ключа не означает согласия на платный облачный запрос.

Ключ сохраняется в хранилище пользователя ОС. Установка для `project` и `--config` не изолируют его по проекту. Кабинет, пароль, регистрацию, CAPTCHA и оплату проходит сам пользователь; ссылки и подсказки есть на странице.

Язык, длину субтитра, форматы, разделение участников по умолчанию и папку результата меняй из чата без страницы: `setup --language auto|КОД --interval СЕКУНДЫ`, `--formats`, `--diarize|--no-diarize`, `--speakers`, `--output`. Выполни команду и одной строкой сообщи, что изменилось. Разовые параметры одной расшифровки («на английском», «с разделением по спикерам») передавай флагами `transcribe` — они настройки не меняют.

## Перед транскрибацией

### Форма подтверждения

Если пользователь прислал только файл или ссылку и сам ничего не сказал о режиме распознавания (язык, длина субтитра, разделение по спикерам, сервис), перед обработкой покажи форму подтверждения:

1. Выполни `transcribe INPUT --plan`. Ответ содержит `formTitle` (вопрос с именем файла), `formPreview` (выровненный блок: файл и четыре параметра — язык, длина субтитра, разделение по спикерам, сервис), `summary` (те же параметры строками) и `settingsCommand`.
2. Покажи форму встроенным инструментом вопроса с вариантами своего клиента (в Claude Code и в Codex есть своя форма выбора). Оформление утверждено пользователем:
   - вопрос — `formTitle` без изменений, заголовок формы — «Расшифровка»;
   - три варианта с описанием и, если форма поддерживает окно предпросмотра (в Claude Code — поле `preview`), с одним и тем же блоком у каждого: `formPreview`, пустая строка, линия `──────────────────────────`, подсказка варианта:

   | Вариант | Описание | Подсказка в предпросмотре |
   |---|---|---|
   | Запустить | Если для файла нет готового результата, запись уйдёт в СЕРВИС — это платно. | Запустить с этими параметрами. Готовые субтитры и кэш — бесплатно, отправка в СЕРВИС — платно. |
   | Изменить параметры | Только для этой расшифровки; сохранённые настройки не меняются. | Спрошу, что поменять, и покажу форму снова с новыми значениями. |
   | Открыть настройки | Страница в браузере: ключи, сервис и параметры по умолчанию, папка результата. | Открою страницу настроек. Когда сохраните — покажу форму снова. |

   СЕРВИС — название выбранного сервиса. Если окна предпросмотра нет, поставь блок `formPreview` в текст вопроса после `formTitle`, строками; если нет и формы выбора — напиши то же сообщением с нумерованными вариантами.
3. «Запустить» — согласие пользователя и на расшифровку, и на облачное распознавание: запусти `transcribe INPUT --allow-cloud` с теми же параметрами, второй раз согласие не спрашивай.
4. «Изменить параметры» — спроси, что поменять, и передай изменения флагами только этой расшифровке: `--language`, `--interval`, `--diarize`/`--no-diarize`, `--speakers`, `--provider`. Сохранённые настройки не меняй. Снова выполни `--plan` с этими флагами и покажи форму ещё раз.
5. «Открыть настройки» — выполни `settingsCommand` и дай ссылку из `url`. Когда пользователь сообщит, что сохранил настройки, снова выполни `--plan` и покажи форму.

Форму не показывай, если пользователь уже назвал режим («на английском», «с разделением по спикерам», «через AssemblyAI»): используй названное, остальное возьми из настроек и действуй по правилам ниже.

### Параметры и способ получения результата

Определи параметры: источник и то, что пользователь назвал для этой расшифровки (язык, форматы, провайдер, диаризация, число спикеров, модель); остальное берётся из сохранённых настроек. Язык по умолчанию — `auto` (автоопределение, у AssemblyAI запасной — русский), длина блока субтитров — 30 секунд. Покажи параметры и источник до обработки. Для URL сообщи, что источник будет прочитан через yt-dlp; cookies не используй автоматически.

Объясни ожидаемый способ получения результата:

- локальный кэш не требует нового API-запроса;
- подходящие авторские, затем автоматические субтитры можно использовать без API;
- если субтитрам не хватает словесных времён или данных спикеров, они не удовлетворяют выбранным требованиям;
- облачное распознавание Deepgram или AssemblyAI может повлечь плату и требует отдельного согласия непосредственно перед вызовом (при форме подтверждения — вариант «Запустить»).

Для `word-timestamps` и диаризации не выдавай фразовые субтитры за точную разметку. Не обещай определить личности людей или точное число спикеров. Модели и ограничения провайдеров смотри в `references/providers.md`.

Если нужна авторизация источника, отдельно сообщи причину и запроси разрешение на cookies. Только после согласия используй соответствующие параметры `--cookies`/`--cookies-browser` вместе с `--allow-cookies`. Не читай браузерные профили и не копируй cookies самостоятельно. Cookies не должны попадать в транскрипт, журналы или API распознавания.

Код `SOURCE_BOT_CHECK` — не требование входа: источник (обычно YouTube) принял запрос за автоматический, чаще всего из-за прокси или VPN. Cookies в этом случае не предлагай; предложи повторить позже или, если подключение идёт через прокси, с `--source-proxy direct` (yt-dlp пойдёт напрямую, мимо прокси). Если помогло, предложи сохранить выбор: `setup --source-proxy direct`. Если в стране пользователя источник открывается только через прокси, прямое подключение не поможет — так и скажи.

Для прямого HTTP(S)-URL объясни до запуска: CLI скачает свежую копию во временную папку, вычислит её SHA-256 и только потом проверит кэш. Это нужно, чтобы сопоставлять именно содержимое, а не меняющийся URL. Скачивание для проверки идентичности само по себе не отправляет медиа в API. После проверки CLI использует подходящий кэш или субтитры; к облачной отправке он может перейти только при отсутствии подходящего локального результата, с `--allow-cloud` и предварительным согласием пользователя.

Расшифровка записи длиннее нескольких минут идёт долго: скачивание, подготовка аудио и ответ сервиса могут занять десятки минут. Запускай её в фоне (в Claude Code — фоновой командой) или с максимальным тайм-аутом команды и не прерывай: если процесс убит после отправки, исход запроса неизвестен и файл блокируется от повторной оплаты.

До запуска обработки покажи фактическую команду и параметры. Для облачного пути получи явное согласие и передай `--allow-cloud`; выбранный в форме подтверждения вариант «Запустить» — такое согласие. Без него облачный запрос запрещён. Для предварительного плана используй `transcribe INPUT --plan`: он показывает параметры до инспекции источника и не скачивает/не отправляет медиа. Не заявляй, что результат будет локальным, пока способ обработки не выбран.

## Результат и восстановление

После выполнения сообщи фактический метод: cache, subtitles или API; если в ответе есть `languageNote`, передай строку «Определён язык: …»; укажи выбранную модель, если CLI её подтвердил, и точность времён (`word`, `phrase` или `none`), если это доступно в результате. Не копируй в ответ личные данные источника, cookies, ключи или сырые ошибки сервиса.

Завершай ответ блоком ссылок на результат — последним, чтобы пользователь сразу его увидел. В нём три кликабельные Markdown-ссылки, каждая отдельной строкой, с короткой подписью вместо пути: `[папка расшифровки](АДРЕС)`, `[субтитры (SRT)](АДРЕС)`, `[текст (TXT)](АДРЕС)`. Адреса бери из поля `links` ответа CLI (`links.folder`, `links.srt`, `links.txt`) дословно: это готовые адреса `file:///…` с закодированными пробелами и кириллицей. Не подставляй вместо них обычные пути (`outputDir`, `files.*`): пробелы в пути ломают ссылку, и клиент показывает голый текст. Не оборачивай ссылку в обратные кавычки, файлы сам не ищи и имена не собирай. Если в `links` нет `srt` или `txt` (формат исключён в `formats`), не выдумывай ссылку: скажи, какого файла нет, и что он соберётся заново из сохранённого результата командой `reformat PATH --formats txt,srt,vtt` локально и бесплатно. То же правило при `reused: true`. Полный путь папки назови текстом только если пользователь просит или ссылка не открылась.

Если в ответе `reused: true`, такой результат уже есть: назови путь `outputDir` и скажи, что новая папка не создавалась. Если пользователю нужны другие форматы или длина субтитра, передай их флагами — результат соберётся заново из кэша без оплаты.

Номер прошлого запуска (run ID) для `resume`, `unlock` и `cleanup RUN_ID` в новом чате находи командой `list`: она показывает последние запуски с названием, статусом, временем, папкой результата и полем `action` (`resume` или `unlock`) и ничего не меняет. Не ищи run ID по служебным папкам вручную.

Если AssemblyAI вернул сохранённый job ID, используй `resume RUN_ID --allow-cloud` только для этого run ID после согласия на облачное чтение. Resume продолжает существующую задачу через GET и не повторяет платную отправку. При неопределённом исходе POST без сохранённого ID (`REQUEST_UNCERTAIN`) не запускай новую транскрибацию и не переключай провайдера: сообщи безопасный код ошибки и объясни, что сервис мог обработать и оплатить запрос. Снять блокировку может только `unlock RUN_ID --confirm-uncertain`, и только после **отдельного явного согласия пользователя на риск двойной оплаты**; предложи ему сначала посмотреть историю запросов в кабинете сервиса. Без флага `unlock RUN_ID` лишь показывает состояние (`confirmation-required`, `not-blocked`) и ничего не меняет. Само согласие на облачную расшифровку согласием на снятие блокировки не является. Блокировку процесса, который был принудительно завершён, CLI снимает сам при следующем запуске.

Для готового результата используй `reformat PATH`, где PATH — папка результата или файл `transcript.json`. Переформатирование локальное, создаёт новую папку и не обращается к API.

Уборку запускай только по просьбе пользователя («убери мусор транскрибатора», «почисти временные файлы»). Общая уборка прошлых запусков — `cleanup` без RUN_ID: сначала `cleanup --dry-run` и покажи строки `summary` и общий объём `total`; удаление — только после отдельного согласия пользователя, командой `cleanup` без `--dry-run`. Удаляются временные файлы, служебные папки завершённых запусков, кэш старше 14 дней (повтор такого файла снова будет платным — скажи об этом) и пустые папки результатов; идущие запуски и записи, нужные `unlock` и `resume`, остаются. Уборка одного запуска — `cleanup RUN_ID --dry-run`, затем `cleanup RUN_ID` после согласия. Не удаляй исходное медиа, готовые результаты, кэш, записи платных запросов или ключи. `--keep-temp` сохраняет временные файлы после успешного результата.

## Ошибки

Перескажи понятный безопасный текст CLI. Отказ сервиса 4xx — `PROVIDER_KEY_REJECTED` (ключ не принят), `PROVIDER_NO_FUNDS` (закончились средства, пополнить в кабинете), `PROVIDER_FORBIDDEN` (нет прав), `PROVIDER_RATE_LIMIT` (лимит запросов), `PROVIDER_REJECTED` — окончательный: оплаты не было, файл не заблокирован, после исправления причины расшифровку можно запустить снова с согласия пользователя. Сбой сервиса 5xx, тайм-аут или сетевая ошибка (`PROVIDER_HTTP`, `PROVIDER_TIMEOUT`, `PROVIDER_NETWORK`) — исход неизвестен, повторная отправка заблокирована; подсказку `unlock` из текста выполняй только по правилам снятия блокировки. Ошибки диска: `FS_ACCESS` (нет прав — предложи другую папку), `FS_NO_SPACE` (нет места), `FS_BUSY` (файл занят другой программой). При `KEY_REQUIRED` или `PROVIDER_KEY_REJECTED` ответ содержит `settingsCommand` — предложи открыть страницу настроек. Ошибка доступа к URL не означает отсутствие субтитров: покажи причину (авторизация, недоступный источник, ограничение частоты или сеть), если CLI её классифицировал. Не обходи ограничения cookies и не повторяй платный POST после timeout, отмены или неоднозначной сетевой ошибки. Если CLI не предоставляет нужную команду, флаг или данные результата, сообщи об этом и остановись.

Ошибки ссылок:
- `SOURCE_MULTIPLE` с полем `choices` — на странице несколько видео. Покажи их формой выбора (номер `item`, название `title`, длительность `durationSeconds`) и повтори ту же команду с `--item НОМЕР`. Параметры и согласие на облако, уже подтверждённые в форме, действуют и для повтора.
- `SOURCE_UNSUPPORTED` — сайт или страница не поддерживается: предложи скачать видео и прислать файл. Обходных путей не ищи.
- `SOURCE_PROCESS_FAILED` — текст содержит ответ yt-dlp (по-английски): перескажи его смысл по-русски.
- Поля `toolOutdated` и `updateCommand` — yt-dlp давно не обновлялся, и обновление может помочь. Предложи обновить программы скилла; после согласия пользователя выполни `updateCommand` (это установка: pip, winget или Homebrew скачают новые версии), затем повтори расшифровку.
- `diagnosticLog` — путь к локальному файлу с полным текстом ошибки yt-dlp. Открывай его только по просьбе пользователя или для разбора сбоя и не вставляй целиком в чат: там бывают адреса и пути.
