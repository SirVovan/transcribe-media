# ADR 0007: единый мастер подключения сервисов

**Статус:** заменено [ADR 0008](0008-settings-page.md) 15.10.2026 (страница настроек; проба и одноразовая форма удалены)
**Дата:** 2026-10-12

## Контекст

После установки пользователю нужно подключить Deepgram или AssemblyAI. Он должен пройти шаги в кабинете сам, не передавая API-ключ ассистенту. Подключение также должно запускаться отдельно после завершения установки и продолжаться в терминале или локальной панели.

## Решение

Использовать общий engine установки и подключения. Терминальная команда `connect` и `serve --connect` продолжают один сценарий с сохранённым состоянием. Панель получает отдельные ограниченные права только на onboarding-действия; приватные команды установщика остаются доступны владельцу session descriptor. Каждый ответ привязан к актуальной revision, устаревший ответ не применяется.

Ключ вводится через существующую локальную защищённую форму и остаётся в хранилище пользователя ОС. Область установки `project` и `--config` не означают изоляцию ключа. Замена существующего значения требует отдельного подтверждения. Проверка Deepgram — только согласуемый GET без аудио; для AssemblyAI безопасная проверка без распознавания помечается как неподдерживаемая. Пробная транскрибация необязательна, ограничена локальным файлом длительностью до 30 секунд и требует отдельного согласия на облачную отправку.

Результаты подключения разделяются на провайдера, сохранение ключа, проверку API и пробу. Кэш и субтитры обозначаются как результаты без API. Для неопределённой отправки сохраняется защита журнала запросов: мастер не отправляет повторный POST автоматически.

## Последствия и отвергнутые варианты

- Второй независимый engine привёл бы к отдельным состояниям и гонкам с установщиком; поэтому используется существующий engine и его сериализация.
- Общая capability панели дала бы браузеру доступ к командам установки и остановки; поэтому onboarding использует собственную ограниченную capability.
- Пробный POST как проверка ключа мог бы отправить медиа и вызвать оплату; поэтому сначала предлагается безопасный probe, а trial отделён отдельным согласием.
- Автоматический повтор после таймаута мог бы создать повторный платный запрос; поэтому неопределённый исход сохраняет существующую защиту от повтора и доступное продолжение только по сохранённому run ID.

Решение дополняет [ADR 0004](0004-shared-installer-engine.md), [ADR 0006](0006-consent-and-interruption.md) и [ADR 0001](0001-request-ledger-and-cache-identity.md), сохраняя общий engine, границы согласия и журнал неопределённых запросов.
