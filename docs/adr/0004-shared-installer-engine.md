# ADR 0004: Общий engine установщика

## Контекст

Установщик должен работать в терминале и через локальную панель, сохраняя совместимость с существующими CLI и API установки. Проверка состояния и установка — отдельные этапы: пользователь должен увидеть план до любых изменений.

## Решение

Обе оболочки используют один `lib/installer/index.mjs` engine как источник состояния и снимка. Engine вызывает существующие config/install API; сервер панели передаёт команды этому engine и не заводит вторую конфигурацию. Проверка отделена от установки, а необязательный первый результат предлагается только после мастера.

## Почему

Единое состояние не расходится между терминалом, панелью и сохранённой конфигурацией. Отдельный этап проверки позволяет явно показать работу без изменений до согласия на установку.

## Последствия

Вопросы терминала и команды локального клиента остаются оболочками одного набора операций. Планы просмотра не записывают настройки и не скачивают программы. Настройки конфигурируются существующим API, включая выбранного и включённого провайдера после успешного сохранения ключа и установленный путь инструментов после установки.
