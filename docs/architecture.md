# Архитектура transcribe-media

## Поток транскрибации

`scripts/cli.mjs` разбирает команду, загружает конфигурацию и связывает источники, задания, провайдеры и форматирование. `lib/config` объединяет настройки клиента и проекта, проверяет параметры распознавания и получает ключ только внутри защищённой операции. Сам ключ не входит в публичные снимки и записи задания.

`lib/sources` определяет локальный файл или ссылку, получает доступные субтитры и при необходимости подготавливает аудио. Для источника фиксируется fingerprint. Прямая HTTP-копия получает identity по содержимому до поиска кэша; перед облачной отправкой источник проверяется снова. Если в источнике несколько аудиопотоков, используется первый. Субтитры YouTube берутся только с исходной дорожки (`-orig` или язык ролика): автоперевод не выдаётся за расшифровку; при языке `auto` — дорожка языка оригинала. У автоматических дорожек первым берётся json3: VTT YouTube «нарастает» (каждая реплика повторяет прошлую строку), разбор VTT такие повторы и реплики-переходы по 10 мс выбрасывает. Скачивание через yt-dlp ограничено 30 минутами плюс длительность ролика, по прямой ссылке — только простоем 60 с без данных.

`lib/jobs` владеет папками запусков, кэшем и журналом платных запросов. Ключ кэша строится из identity источника, параметров распознавания и расположения файла учётных данных; временные таймауты в него не входят. Журнал и блокировка не дают повторно отправить запрос с неопределённым исходом. Файл блокировки `.lock` хранит pid, имя компьютера и метку владельца: блокировку завершённого процесса на этом компьютере следующий запуск перехватывает (через `.lock.recovery`), после чего журнал проверяется как обычно. Неопределённый исход снимает только `unlock RUN_ID --confirm-uncertain` — решение пользователя о риске двойной оплаты. Ответ сервиса 4xx — окончательный отказ без оплаты: запрос помечается `failed` с `definitive`, и файл можно отправить снова (если задание AssemblyAI ещё не создано). Если у AssemblyAI уже сохранён идентификатор задания, `resume` продолжает его. Сырой ответ провайдера сохраняется до форматирования, поэтому локальную обработку результата можно восстановить отдельно от оплаты. Временные файлы задания регистрируются и удаляются только внутри его временной папки. Общая уборка `cleanupWork` (`cleanup` без RUN_ID) проходит `jobs`, `cache`, `requests` и пустые папки результатов `<название>-<runId>`; запуски моложе часа или с живой блокировкой и всё, что нужно `unlock`/`resume`, она пропускает, а старый кэш удаляет вместе с записью `complete` журнала. Повтор с тем же ключом кэша, длиной субтитра и форматами `findResult` находит готовую папку результата по её `job.json` (поиск идёт по папкам результатов, поэтому переживает уборку), а только что созданный запуск удаляет `discardJob`. `listJobs` (`list`) перечисляет запуски из `jobs` с действием `resume` или `unlock`.

`lib/providers` задаёт возможности и проверку моделей Deepgram и AssemblyAI (язык `auto` — автоопределение: Deepgram `detect_language`, AssemblyAI `language_detection` с запасным `ru`), классифицирует ответы 4xx в понятные коды, считает тайм-ауты от размера и длительности записи (`requestTimeouts`), выполняет распознавание или продолжение задания и приводит ответы к общей модели транскрипта. `lib/transcript` форматирует эту модель в выбранные TXT, SRT, VTT и JSON результаты.

Тексты ошибок источников, сервисов и настроек — постоянные строки без путей, адресов и ответов сервисов (пометки `cliSafe`, `installerSafe`); CLI и мастер показывают их как есть. Системные ошибки файлов (нет прав, нет места, файл занят) переводит в понятный текст `lib/errors.mjs`; остальные внутренние ошибки показываются общей фразой, чтобы не раскрыть пути и данные.

## Точки входа и установка программ

Запускатели: `Установить.cmd` → `start.ps1` (Windows), `start.sh` (macOS/Linux). Корневые файлы — обёртки: сами запускатели лежат в `skills/transcribe-media/scripts/`, чтобы работать и после установки из GitHub, где есть только папка скилла. С `--chat` они запускают `installer.mjs serve --detach --open`: мастер работает в фоне, команда сразу печатает JSON сессии (`url`, `sessionPath`, `pid`, `log`) и завершается, панель открывается в браузере. Node.js ищут и ставят общие `scripts/node-bootstrap.ps1` и `scripts/node-bootstrap.sh` скилла.

Мастер — `skills/transcribe-media/scripts/installer.mjs` с командами `start`, `serve`, `connect`, `settings`; разрешённые параметры показывает `installer.mjs help`. `settings` открывает страницу настроек `/setup`: переиспользует работающий сервер сессии или запускает `serve` в фоне тем же способом, что `--detach`. `connect` — подключение сервиса в терминале со скрытым вводом ключа. Клиентские команды печатают ход операции в stderr, итог — JSON в stdout. Ошибки CLI «нет ключа» и «ключ отклонён» возвращают `settingsCommand` — команду открытия страницы. Второй скилл `skills/transcribe-settings` (только явный вызов `/transcribe-settings`) запускает ту же команду; установщик кладёт его рядом с основным.

Установка из GitHub. Сборка `node scripts/build-github.mjs` кладёт в отдельную папку содержимое ZIP, README, LICENSE и описание плагина Claude Code (`.claude-plugin/marketplace.json`, `plugin.json`; плагин — корень репозитория, скиллы — `skills/`). Входы: фраза ассистенту со ссылкой (ассистент скачивает архив репозитория и идёт по `references/install.md` как с пакетом), `/plugin install` и `npx skills add`. Два последних кладут скилл сами, поэтому первая настройка выбирает `select --in-place`: `installPackage({inPlace:true})` не копирует скилл и ставит только программы. Признак первого запуска для `SKILL.md` — нет `config.json` в папке настроек.

`lib/install` ищет программы не только в PATH, но и в известных местах (Windows: WinGet, Program Files\nodejs, Chocolatey, Scoop; macOS: Homebrew, MacPorts, ~/Library/Python) и проверяет EJS командой `yt-dlp --verbose --simulate about:invalid`. Недостающее ставится способом разработчиков: Windows — winget (`OpenJS.NodeJS.LTS`, `Gyan.FFmpeg.Essentials`, `yt-dlp.yt-dlp`), macOS — Homebrew; yt-dlp из pip обновляется `pip install -U "yt-dlp[default]"`; без winget или Homebrew — ручной шаг. Linux пока скачивает программы в личную папку. Отсутствие EJS — предупреждение, установка скилла продолжается. Найденные пути записываются в настройки скилла.

## Установка и страница настроек

`lib/installer/index.mjs` владеет общим состоянием мастера установки. `lib/installer/service.mjs` добавляет к нему состояние подключения `connection` — основной сервис, источник ключа (`missing`, `saved`, `env`) и проверка по каждому сервису — и действия страницы: обновить, сохранить ключ с проверкой, проверить снова, удалить ключ, сделать основным, а для терминала — скрытый ввод (`providerKey`). Сам ключ в состоянии не хранится. `lib/config` остаётся владельцем хранилища ключей, `lib/providers/verification.mjs` — проверки: `checkKey` делает один GET без аудио (Deepgram `/v1/auth/token`, AssemblyAI `/v2/transcript?limit=1`, тело не читается, перенаправления запрещены), `saveCheckedKey` записывает ключ только после ответа сервиса и не записывает отклонённый (401/403). Проверка привязана к ревизии ключа: после замены ключа она сбрасывается. Если у основного сервиса нет ключа, основным становится сервис с только что сохранённым ключом. Старое состояние пошагового мастера (`serviceOnboarding`, schemaVersion 1) читается без ошибки; из него переносится только подтверждённая проверка.

`lib/installer/terminal.mjs` и `lib/installer/dashboard` показывают ход установки; тексты хода — `lib/installer/progress-text.mjs`, тексты и ссылки сервисов — `lib/installer/provider-guides.mjs` (модуль без зависимостей, его загружает и Node, и страница). Страница настроек — `dashboard/setup.html`, `setup.js`, `setup.css`. HTTP-транспорт `lib/installer/server.mjs` слушает только 127.0.0.1 и проверяет Host и Origin. Управляющий токен (`capability`) выдаётся CLI через файл сессии и принимает белый список команд без ключей. Токен страницы (`browserCapability`) встраивается только в `/setup` и открывает лишь `POST /api/settings`: JSON, обязательный Origin, ограничение размера, белый список полей; ключ принимает только действие `save-key`. Ключ не попадает в состояние, журнал, ответы API и argv.

Состояние и descriptor сессии позволяют продолжить работу после закрытия интерфейса. Lease не допускает второго владельца; `--recover` предназначен для восстановления своей сессии после завершения её процесса. При отмене активная установка сначала достигает безопасной границы, затем освобождается сессия; уже сохранённый результат не откатывается. Без действий сервер выключается через 30 минут.
