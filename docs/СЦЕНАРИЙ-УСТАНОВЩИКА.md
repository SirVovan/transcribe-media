# Сценарий установки и настройки transcribe-media

Этот документ описывает путь пользователя от архива до готового скилла и отдельный мастер подключения сервиса. Результат 129/129 — исторический снимок mock-набора до ремонтов 12 октября, а не текущая приёмка. Новый итоговый счёт пока не фиксируем: продолжается F1, результат может измениться. UI подключения остаётся без приёмки; пользователь выбрал ручное тестирование. Это не подтверждает реальные установки, сетевые загрузки, работу API или обнаружение скилла клиентом.

## Два входа

Сначала пользователь распаковывает пакет в отдельную папку.

- **Из локального чата:** открывает папку как проект или рабочий каталог клиента и просит ассистента установить скилл. До регистрации скилла ассистент читает `УСТАНОВИТЬ-ИЗ-ЧАТА.md`. Native bootstrap показывает план, получает отдельное согласие на проверку Node и при необходимости — на загрузку приватной копии. После этого он запускает управляемый `serve` и возвращает URL панели, `sessionPath`, `nodePath` и идентификатор сессии. Подробный порядок native-команд и клиентских действий дан в [УСТАНОВИТЬ-ИЗ-ЧАТА.md](../УСТАНОВИТЬ-ИЗ-ЧАТА.md).
- **Из терминала:** Windows-пользователь дважды щёлкает `Установить.cmd` или запускает `start.ps1`; на macOS/Linux запускает `start.sh`. Вопросы задаются в терминале, состояние показывается в локальной панели. При необходимости launcher показывает план установки Node и запрашивает явное согласие.

Клиентский локальный контекст должен видеть распакованную папку и разрешать запуск локальных команд. Если этого нет, чатовый способ недоступен; используйте терминал. Инструкция не зависит от отдельной кнопки выбора папки с фиксированным названием: способы открытия локального проекта отличаются в клиентах.

## Этапы мастера

Мастер ведёт пользователя по шести этапам:

1. **Выбор:** выбрать Codex, Claude Code или оба; область пользователя или проекта.
2. **Проверка программ:** отдельно согласовать проверку Node.js, FFmpeg, ffprobe и yt-dlp.
3. **Установка:** показать актуальный план. Установка и обновление выполняются только после отдельного согласия с текущим `planId`.
4. **Подключение сервиса:** мастер открывает страницу настроек `/setup`; пользователь сохраняет и проверяет ключ Deepgram или AssemblyAI либо откладывает подключение. Ключ не попадает в чат или общую панель состояния.
5. **Настройки:** подтвердить или поменять язык (по умолчанию — автоопределение), длину одной строки субтитров (по умолчанию 3 с), форматы, разделение участников, число спикеров и папку результата.
6. **Завершение:** показать сводку и сохранить согласованные параметры.

После установки мастер сам открывает в браузере страницу настроек. Позже её открывает просьба в чате («Открой настройки транскрибации»), команда `/transcribe-settings` (в Codex — `$transcribe-settings`) или команда `node "<путь-к-пакету>/skills/transcribe-media/scripts/installer.mjs" settings`. На странице — карточки Deepgram и AssemblyAI со ссылками на регистрацию и создание ключа, поле ключа и кнопка «Сохранить и проверить», а также настройки расшифровки. Кабинет сервиса вы открываете и проходите сами.

Кнопка «Сохранить и проверить» отправляет сервису один бесплатный проверочный запрос без аудио. Ключ, который сервис не принял, не сохраняется; если сервис недоступен, ключ сохраняется со статусом «не проверен». Ключ вводите только на странице, не в чате. Он хранится для пользователя ОС; область установки `project` и `--config` не изолируют ключ по проекту. По умолчанию язык определяется автоматически, длина одной строки субтитров — 30 секунд.

Проверка программ не означает согласие на установку. Установка программ и копирование скилла не запускают транскрибацию и не отправляют медиа в API. Возможная платная облачная обработка требует своего согласия. Подключение сервиса можно отложить и продолжить позже на странице настроек.

Ручной пользовательский сценарий из терминала и список команд основного CLI описаны в [references/usage.md](../skills/transcribe-media/references/usage.md).

## Локальная панель

В ходе bootstrap native launcher может открыть простую HTML-панель первого этапа. Она показывает состояние Node и операции загрузки; согласия и ответы остаются в канале запуска — чате или терминале. Подсказка панели соответствует выбранному каналу. После запуска Node мастер обновляет переход и показывает ссылку на основную панель.

Основная панель показывает шаги, состояние программ, текущую операцию, ожидание ответа, последние события и связь с локальным процессом. В ней нет формы управления: ответы остаются в чате или терминале, ключ вводится только в отдельную loopback-форму. Неизвестное состояние и ожидание согласия не обозначаются как активная загрузка. Процент показывается только при измеренных `loaded` и `total`; иначе отображается состояние операции без выдуманного числа.

Панель получает актуальный снимок состояния. Закрытие вкладки не останавливает процесс; повторное открытие по локальной ссылке показывает текущее состояние. Сам `serve` штатно закрывается командой `stop`, ждёт безопасного завершения текущей операции и очищает свой descriptor. После 30 минут без управляющих команд процесс закрывается автоматически, но активную операцию idle timeout не прерывает.

## Продолжение и восстановление

Команда `status --session PATH` показывает текущее состояние безопасной сессии. Долгая клиентская команда ожидает результат и опрашивает его; вторую установку параллельно не запускают.

Если пользователь отменяет установку, мастер дожидается безопасного завершения текущей низкоуровневой операции. При статусе `cancel-pending` нужно дождаться результата; установленные файлы не удаляются. Если процесс аварийно завершился, сначала проверяют `status`, затем при необходимости запускают `serve --recover` с тем же состоянием и только для собственного lease с подтверждённым завершением процесса. При живом или неизвестном процессе восстановление не запускают.

После завершения пользователь открывает новый чат в выбранном клиенте и просит использовать `transcribe-media`. Если скилл не обнаружен, можно перезапустить клиент. Само обнаружение в реальных установках пока не проверено.
